# tests · 测试用例与运行记录

课程明确要求："课程不仅要求程序和 SQL 能够运行，还要求同学们能够解释自己的设计思路，并**通过运行结果、测试记录和实验报告验证其正确性**。"

本目录是这些"验证证据"的落点。

## 放什么

| 类型 | 说明 | 对应课程要求 |
|---|---|---|
| 约束验证 | 非法数据被拒绝的运行截图/输出 | 第 4 周：非法数据被拒绝 |
| 权限验证 | 越权操作失败的运行证据 | 第 4 周：越权操作失败 |
| 查询验证 | 多表查询与视图的结果正确性 | 第 4 周：查询结果正确 |
| 规范化与迁移验证 | 模式拆分、约束拦截与语义保持 | 第 6 周：无损分解与语义保持 |
| 事务验证 | 正常提交与失败回滚 | 第 3 阶段：事务边界清楚 |
| 并发验证 | 锁等待、隔离现象、死锁分析 | 第 3 阶段：有证据 |

## 两个门槛

本项目有**两套**验证手段，用途不同，不能互相替代：

| | 快照（baseline） | 回归测试（regression） |
|---|---|---|
| 目的 | 存下"迁移前是什么样"，供人工比对 | 断言"必须成立的条件"，让机器判定 |
| 失败方式 | 不会失败，只会 diff 出不同 | 必须返回非零退出码（Non-zero Exit Code） |
| 数字来源 | 直接从库里查出来 | 硬编码期望值，由快照基线固化而来 |
| 落点 | `baseline/` | [`regression.sql`](regression.sql) 与专项测试 `NN-*.sql` |

串起来用：**先跑快照建基线，再把关键数字固化成回归测试的期望值**。

## 核心脚本清单

| 文件 | 类型 | 用途 | 退出码机制 |
|---|---|---|---|
| [`regression.sql`](regression.sql) | 全库自动化回归入口 | 覆盖 18 表结构、券模板、销售额 D 口径、明细不变量、积分台账对账、登录凭据质量等 14 项硬断言 | 失败触发 `THROW 51000`，`sqlcmd -b` 退出码 1 |
| [`01-migration-verification.sql`](01-migration-verification.sql) | 迁移专项正反例 | 针对核销有效区间 `ck_coupon_used_time_range` 与外键 `fk_coupon_template` 5 项测试 | 失败触发 `THROW 51000`，`sqlcmd -b` 退出码 1 |
| [`01-migration-verification.md`](01-migration-verification.md) | 测试报告与记录 | 迁移测试输入输出、执行日志与全链路证据 | 文档归档 |

## 约定

- **断言只锁「种子数据」，不锁「业务增长」**：`regression.sql` 里凡是硬编码的绝对数字（如 TC-10 的 1,926 单 / 23,762.00 元）都限定在 `business_date < '2026-10-01'` 的 v0.1 种子区间内统计。应用上线后顾客会真的下单，若把断言写死在「全库」，正常点一杯就会让回归变红（2026-11-08 实测：两张演示单把数字抬到 1,928 单 / 23,770.00 元）。运行期新增的数据只打印、不参与断言。
- 每个测试一个 `.md`：**目的 → 输入 → 期望 → 实际输出 → 结论**
- 运行证据（输出文本、截图）与被测脚本放在同一目录
- 测试文件命名：`NN-<被测对象>-<场景>.md`，如 `01-migration-verification.md`
- **测试脚本失败必须返回非零退出码**（`THROW` 或 `RAISERROR(...,16,1)` 配合 `sqlcmd -b`），任何断言失败必须立即阻断流水线，绝不允许静默掩盖。
