# tests · 测试用例与运行记录

课程明确要求："课程不仅要求程序和 SQL 能够运行，还要求同学们能够解释自己的设计思路，并**通过运行结果、测试记录和实验报告验证其正确性**。"

本目录是这些"验证证据"的落点。

## 放什么

| 类型 | 说明 | 对应课程要求 |
|---|---|---|
| 约束验证 | 非法数据被拒绝的运行截图/输出 | 第 4 周：非法数据被拒绝 |
| 权限验证 | 越权操作失败的运行证据 | 第 4 周：越权操作失败 |
| 查询验证 | 多表查询与视图的结果正确性 | 第 4 周：查询结果正确 |
| 事务验证 | 正常提交与失败回滚 | 第 3 阶段：事务边界清楚 |
| 并发验证 | 锁等待、隔离现象、死锁分析 | 第 3 阶段：有证据 |

## 两个门槛

本项目有**两套**验证手段，用途不同，不能互相替代：

| | 快照（baseline） | 回归测试（regression） |
|---|---|---|
| 目的 | 存下"迁移前是什么样"，供人工比对 | 断言"必须成立的条件"，让机器判定 |
| 失败方式 | 不会失败，只会 diff 出不同 | 必须返回非零退出码 |
| 数字来源 | 直接从库里查出来 | 硬编码期望值，由快照基线固化而来 |
| 落点 | `baseline/` | 根目录 `NN-<被测对象>-<场景>.sql` |

串起来用：**先跑快照建基线，再把关键数字固化成回归测试的期望值**。

## 子目录

| 目录 | 内容 |
|---|---|
| `baseline/` | 迁移前快照脚本与实测结果，见 [`baseline/README.md`](baseline/README.md) |
| 根目录 | 回归测试与逐条用例说明 |

## 约定

- 每个测试一个 `.md`：**目的 → 输入 → 期望 → 实际输出 → 结论**
- 运行证据（输出文本、截图）与被测脚本放在同一目录
- 测试文件命名：`NN-<被测对象>-<场景>.md`，如 `01-orders-not-null-violation.md`
- **测试脚本失败必须返回非零退出码**（`RAISERROR(...,16,1)` 或 `THROW`），
  只 `PRINT` 一段"失败 N 条"然后正常结束的脚本，在 CI 眼里永远是通过的
  —— 现有 `01-migration-verification.sql` 就是这种写法，已在第 6 周登记为待办
