## 1. 现象与矛盾描述

[`project/docs/normalization.md`](../../project/docs/normalization.md) 的**结论摘要（§0）**与**判定明细（§3）**对同一批 17 张表给出了两套互斥的范式统计：

- **§0** 说「标准 BCNF **12 张**」+「有意的反规范化（2NF+）**5 张**」；
- **§3** 的 17 行判定表逐个表判定，实际结果是「**14 张 BCNF + 3 张 2NF**」。

两套数各自都能凑满 17（`12+5` / `14+3`），所以不是漏表，而是**结论段与判定表没有对齐**。

另有一处连带矛盾：§0 同一张表里既写「**3NF 关系 0 张**」，又写「有意的反规范化（**2NF+**）5 张」。
若真有 5 张表不满足 3NF，那「3NF 关系 0 张」这句话就没有意义了（2NF 表的 3NF 判定必然是不满足）；
§0 紧挨着的「决定因素全为超码，**无任何部分依赖与传递依赖**」也与 2NF 结论直接冲突。

**本 Issue 只提报，不修改** —— 该文件由 hezhlin5 执笔，判定口径应由作者统一，避免我覆盖他人结论。

## 4. 建议解法与行动方案

三个问题，按优先级排列，**都请作者定夺**：

### Q1（必须定）§0 与 §3 哪个是你要的结论？

我按判定表逐行数得到 **14 BCNF + 3 张 2NF**。若 §3 是准的，§0 的两行需要改成 14 / 3；
若是 §0 为准，则 §3 有 3 行判定写错了（或另有 2 张表未进表）。

### Q2（口径问题）`points_balance` / `amount_due` / `subtotal` 标 2NF 是否妥当？

这三列都是**被主码函数决定**的（`member_id → points_balance`、`order_id → amount_due`、
`order_detail_id → subtotal`）。按定义，决定因素是超码，**不违反 2NF / 3NF / BCNF** ——
它们的冗余来自"跨行聚合快照""跨表派生"，属于**更新异常**范畴，但不是**范式**范畴。

所以术语上，写成「受控冗余 / 有意反规范化（派生列）」比「2NF」更准确；
而 §0 的「完全杜绝更新异常」这个说法，在这三列存在时就站不住（改明细不同步小计就会不一致）。

> 这条不影响结论的工程价值 —— 保留冗余是对的，要动的只是**标签**。若你认为学术上就该标 2NF，
> 请回一句说明，我按你的口径统一其余文档，不再提。

### Q3（连带）§0 内部两句话要先自洽

「3NF 关系 0 张」与「反规范化 5 张（2NF+）」同时成立则矛盾；
「无任何部分依赖与传递依赖」与 3 张 2NF 同时成立也矛盾。Q1 定了之后这两句要一起改。
