# 会话开工对齐 (agent-session-start)

## 适用场景
每次开启新的 IDE 会话、或者开始一段独立编码/文档任务前，作为发送给 Agent 的第一条指令，确保 Agent 不盲目发挥，先与仓库最新状态对齐。

## 提示词（直接复制使用）

```markdown
我们正在进行奶茶店数据库实验课程项目（茶颜小铺 · 单店）。
开发模式为 Agent 原生 + 二人对等协作。
在动手编写任何代码或修改文档之前，请先执行「开工对齐 SOP」并用 3 句话回显确认：

1. 检查最新状态：
   - 查阅当前活跃周目录（如 weeks/week02/README.md），确认当前阶段目标与未决项；
   - 检查 harness/issues/README.md 中是否有指派给你或待处理的高优先级 Issue；
   - 查看最近 3 次 git 提交历史，了解舍友刚动了什么。
2. 约束检查：
   - 严格遵守 harness/conventions/ 下的命名规范与 02-sql-style.md 风格；
   - 保持 project/sql/99-rebuild.sql 的一键重建基准；
   - 严禁对未修改区域的 Markdown 表格与行号进行全局重新排版，以避免 Git 冲突。

我本轮要进行的任务是：[请在此填写本次目标，例如：编写原料表的字段字典 / 编写数据生成原型]
请先简要回显你对当前上下文的理解，再开始执行。
```

## 效果
- 消除“上下文漂移（Context Drift）”；
- 阻止 Agent 刚开局就修改错分支或全篇重排 Markdown 造成 Git 冲突；
- 强制 Agent 自觉检查 `harness/issues/` 中待处理的排雷任务。

## 注意
- 每次提示时，在中括号内简要填写本次目标即可；
- 若本轮目标涉及具体 Issue，可直接指定编号，如 `本次任务是解决 ISSUE-003`。
