# 05 · AI 协作与留痕规范

## 1. 课程要求（原文）

> **AI 使用边界**：允许使用大模型，但须**保留提示词、候选答案、人工修改与验证证据**；AI 生成结果不能替代 SQL 测试、约束验证和个人答辩。

> **提示与常见问题**：AI 可以用来辅助梳理流程、提出候选实体，但必须能解释和修改，不能直接照抄。**记录下使用 AI 协助与人工修改。**

本规范把上述要求固化成可执行的格式，让留痕**可审计、可复现**，而不是事后补写。

## 2. 四条底线

| # | 底线 | 说明 |
|---|---|---|
| 1 | **必须留痕** | 每次实质使用 AI 都在当周周报中记录 |
| 2 | **必须能解释** | 凡提交的 AI 产物，组内任一成员都要能讲清楚为什么这么设计 |
| 3 | **必须验证** | AI 生成的 SQL 必须实际跑过；AI 给出的数据/结论必须交叉核实 |
| 4 | **不得照抄** | 直接采纳 AI 输出而不理解、不修改，视为违反 |

> 底线 2 是答辩的生死线。**AI 可以帮你写，但不能帮你答。**

## 3. 标准记录格式

周报与阶段报告中的「AI 使用记录」统一用此表：

```markdown
## AI 使用记录

| 项 | 内容 |
|---|---|
| 使用目的 | 用它做什么（一句话） |
| 提示词要点 | 提了什么要求（可引用关键句） |
| AI 输出 | 它给了什么（概括，不粘贴全文） |
| **人工修改与验证** | ① 改了什么 ② 怎么验证的 ③ 结论是否被推翻 |
| 存疑 / 未验证 | 哪些没核实、为什么 |
```

> **核心是「人工修改与验证」这一栏。** 只写 AI 输出了什么、不写人做了什么，等于没有留痕。

## 4. 什么该记、什么不必记

| 记 | 不记 |
|---|---|
| 影响设计决策的对话（选型、建模、约束设计） | 琐碎的格式调整 |
| 生成了实际提交内容的对话 | 纯检索（查某个语法） |
| **AI 出错并被人工纠正的案例** ⭐ | 无关寒暄 |
| AI 给出但**被否决**的方案 | |

> ⭐ **AI 出错并被纠正的案例最有价值**——它直接证明"人工在把关"，是答辩时的有力证据。

## 5. 分级：AI 输出与人工判断必须可区分

| 级别 | 含义 | 处理 |
|---|---|---|
| **A 直接采纳** | 输出经验证无误 | 仍需在记录中说明验证方式 |
| **B 修改后采纳** | 部分采纳，人工调整 | 必须写明改了什么、为什么 |
| **C 仅作参考** | 启发了思路但未采纳 | 记为候选方案，说明否决理由 |
| **D 否决** | 输出有误或不可用 | **必须记录**，说明错在哪 |

## 6. 存放位置

| 内容 | 位置 | 进 git |
|---|---|---|
| 正式提交用的 AI 使用记录 | `weeks/submissions/vX.Y/ai-usage.md` | ✅ |
| 周度 AI 使用记录 | `weeks/weekNN/README.md` 的「AI 使用记录」小节 | ✅ |
| 经整理、可复用的提示词 | `harness/prompts/` | ✅ |
| 原始会话日志、大段原始对话 | `harness/logs/raw/` | ❌ gitignore |

### 6.1 可复用提示词入库格式（`harness/prompts/`）

一个提示词一个文件，命名 `<用途>.md`：

```markdown
# <提示词用途>

## 适用场景
什么时候用它

## 提示词
（可直接复制的全文）

## 效果
用过几次、效果如何、有什么坑

## 注意
需要人工检查什么
```

## 7. 验证证据的落点

AI 生成的 SQL / 数据 / 结论，其验证证据放：

| 类型 | 位置 |
|---|---|
| SQL 运行结果 | `project/tests/` 下对应的测试记录 |
| 数据核验 | `project/data/README.md` 的说明 + 校验值 |
| 交叉核实 | 在 AI 记录中写明"用 X 源核实了 Y" |

## 8. 明确禁止

| 禁止 | 原因 |
|---|---|
| 把 AI 输出当作验证结果 | 课程明确"AI 生成结果不能替代 SQL 测试、约束验证" |
| 提交未经运行的 AI 生成 SQL | 无法保证正确性 |
| 在答辩中无法解释自己提交的设计 | 底线 2 |
| 伪造留痕（事后补写未发生的过程） | 违反学术诚信；如实记录"忘了记"也比编造好 |
| 把数据库口令、服务器地址发给 AI | 安全风险 |

## 9. 一句话总结

> **AI 负责产出草稿，人负责判断与验证。** 留痕的价值不在于证明"用了 AI"，而在于证明"人把关了"。
