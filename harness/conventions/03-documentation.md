# 03 · 文档与报告格式规范

## 1. 三类文档

| 类型 | 位置 | 目的 |
|---|---|---|
| **周报** | `weeks/weekNN/README.md` | 记录本周做了什么、产出什么、卡在哪 |
| **阶段报告** | `weeks/submissions/vX.Y/report.md` | 提交给课程评分 |
| **设计文档** | `project/docs/` | 面向最终项目的 ER 图、数据字典等 |

## 2. 周报模板（`weeks/weekNN/README.md`）

```markdown
# weekNN · 第 N 周

**理论内容**：…
**项目任务**：…

## 文件对照
| 文件 | 中文标题 |
|---|---|

## 本周产出摘要
| 交付物 | 状态 | 所在 |
|---|---|---|

## 已并入 project 的产出
> 本周产出的 xxx.sql 已并入 project/sql/NN-xxx/

## 本周遇到的问题与处理
| 问题 | 处理 | 结论 |
|---|---|---|

## AI 使用记录
（格式见 05-ai-collaboration.md）

## 下周计划
```

## 3. 阶段报告模板（课程硬性要求）

课程要求阶段报告包含**设计思路、实验过程、实验总结**三部分。模板：

```markdown
# 阶段X 报告 · vX.Y

## 1. 设计思路
  1.1 业务背景与范围
  1.2 设计目标
  1.3 关键设计决策与取舍（含被否决的方案及原因）   ← 答辩重点
  1.4 数据模型说明

## 2. 实验过程
  2.1 环境与准备
  2.2 实施步骤（可复现，含命令）
  2.3 遇到的问题与解决过程                       ← 过程证据
  2.4 验证与测试记录（引用 project/tests/）

## 3. 实验总结
  3.1 完成情况对照课程要求
  3.2 尚未解决的问题
  3.3 下一阶段计划

## 附录
  A. AI 使用记录
  B. 组内分工表
```

### 3.1 「设计思路」必须写到能答辩的程度

课程评分明确包含"能否解释清楚设计思路与实验过程"。因此：

- **决策必须有理由**。写"用 `DECIMAL(10,2)` 存金额"，要补一句"因为 `FLOAT` 有精度误差，金额不允许"。
- **记录被否决的方案**。为什么不做多门店？为什么不做批次追溯？"我们考虑过但放弃"和"我们没想到"是完全不同的答辩表现。
- **边界要有依据**。数据边界清单里每一项都要有理由。

## 4. 写作规范

| 规则 | 说明 |
|---|---|
| 标题层级 | 从 `##` 开始（`#` 留给文档标题） |
| 表格 | 优先用表格承载结构化信息（角色、字段、对照） |
| 图 | 用 Mermaid（可版本控制、可 diff），**不用截图** |
| 代码块 | 必须标注语言（```sql / ```powershell / ```text） |
| 术语 | 全文中英文术语首次出现时给出对照，如"配方（BOM）" |
| 结论先行 | 每节开头一句话给结论，再展开 |

### 为什么图用 Mermaid 而非截图

截图无法 diff、无法搜索、仓库体积大；Mermaid 是纯文本，改动能在 git 里看见。**流程图必须用 Mermaid**。

## 5. 状态标记

全项目统一使用：

| 标记 | 含义 |
|---|---|
| ✅ | 已完成 |
| 🔄 | 进行中 |
| ⬜ | 未开始 |
| ⚠️ | 有风险 / 待处理 |
| ❌ | 已否决 / 不做 |

## 6. 待办与未决项

文档中未解决的问题**不要删掉**，写进「待确认」或「遗留问题」小节，标明责任人。**抹掉未决问题会在答辩时变成盲区。**
