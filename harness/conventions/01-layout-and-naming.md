# 01 · 目录与命名规范

> 上位文档：[`../../STRUCTURE.md`](../../STRUCTURE.md)
> 本文档是该方案的**可执行规范版**。

## 1. 命名总则

**目录名与文件名全部使用英文**，文档内容使用中文。

**禁用**：空格、中文、大写字母、下划线（有序前缀中的 `-` 分隔符除外）。

## 2. 目录与文件命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 目录 | 全小写，单词用 `-` 连接 | `data-availability`、`business-requirements` |
| 有序目录 / 脚本 | 两位数字前缀 + `-` | `00-bootstrap`、`01-schema`、`99-rebuild.sql` |
| 周次目录 | `week` + 两位数字 | `week01` … `week17` |
| 版本目录 | `v` + 主.次 | `v0.1`、`v1.0` |
| 文档 | 全小写，`-` 连接，`.md` | `business-requirements.md` |
| SQL 脚本 | 全小写，`-` 连接，`.sql` | `create-tables.sql` |
| 课程材料 | `lecture-weekNN` / `ppt-weekNN` | `lecture-week01.md` |

### 为什么用两位数字前缀

`00-` → `99-` 的前缀让**文件管理器排序 = 执行顺序**。新人 clone 后不需要读文档就知道先跑哪个。这是"可复现"最便宜的保障。

### 编号前缀（三套，别混）

文档里同时存在**三套编号**，前缀不同、含义不同：

| 前缀 | 含义 | 定义处（唯一真相源） |
|---|---|---|
| **`D-01`～`D-12`** | 第 2 周的**设计决策** | [`weeks/week02/schema-design.md`](../../weeks/week02/schema-design.md) |
| **`D1`～`D8`** | ISSUE-001 / 002 / 003 的**裁决结论** | [`weeks/week02/issue-review.md`](../../weeks/week02/issue-review.md) |
| **`DOM-01`～`DOM-16`** | **域**（取值集合） | [`project/docs/data-dictionary.md`](../../project/docs/data-dictionary.md) 第一节 |

> ⚠️ **别混**：`D-04`（设计决策）**≠** `D4`（裁决结论）；`DOM-06` 是第三套。
> 带小写后缀的如 `D-05a`，表示 `D-05` 的一个**分支决策**。
> 各文档**引用即可，不要另抄一份**（§5）。

## 3. 可读性补偿

全英文命名牺牲可读性，用两个办法补回来：

1. **每个目录放 `README.md`**，说明用途（取代散落的 `.gitkeep`）
2. **`weeks/weekNN/README.md` 里放中英对照表**：

```markdown
| 文件 | 中文标题 |
|---|---|
| business-requirements.md | 第一周报告 · 业务需求分析 |
| data-availability.md | 数据可得性对比表 |
```

## 4. 四个顶层域

| 域 | 职责 | 放什么 | **不放什么** |
|---|---|---|---|
| `course/` | 资料（只读） | 课程原件 + 转写稿 | 自己的改编稿 |
| `weeks/` | 过程 | 周报、草稿、提交快照 | 最终版代码 |
| `project/` | 成果 | SQL、数据、应用、设计文档、测试 | 草稿、周报 |
| `harness/` | 协作 | 规范、提示词、小组、AI 留痕 | **任何业务内容** |

## 5. 草稿 → 正式的升级路径

```
weeks/weekNN/ 草稿
      │  验证通过、纳入正式流程
      ▼
project/<对应目录>/ 正式文件
      │
      ▼
weeks/weekNN/README.md 留一行记录
```

> **禁止**同一份内容在两个地方各自演化。

## 6. 违规判定

| 情形 | 判定 |
|---|---|
| `harness/` 里出现 `.sql` 或数据文件 | ❌ 违反边界 |
| `project/` 里出现周报草稿 | ❌ 违反边界 |
| `course/` 里的原件被修改 | ❌ 违反只读约定 |
| 出现中文文件名 | ❌ 违反命名总则 |
| 同一个 SQL 在 `weeks/` 与 `project/` 并存 | ❌ 违反升级路径 |
