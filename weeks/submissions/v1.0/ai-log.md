# AI 使用记录（ai-log）· 阶段二 v1.0

> **课程要求**：允许使用大模型，但须**保留提示词、候选答案、人工修改与验证证据**；
> AI 生成结果**不能替代 SQL 测试、约束验证和个人答辩**。
>
> **本文档的定位**：**阶段汇总**（第 5—9 周）。逐周的完整记录在各周周报（`weeks/week05`—`week07`）

## 3. AI 出错并被人工纠正的案例（最有价值的一节）

| # | AI 的说法 / 做法 | 人工怎么发现的 | 纠正结果 |
|---|---|---|---|
| **3-1** | 报"字段列数 121"、又说"161" | 两次数字对不上，要求逐文件重数 | **括号感知解析**得 **132 列**（v0.1 提交点） |
| **3-2** | 断言"`weeks/week01` 从未记录过第 2 周修正"是**新发现** | 人工要求先检索再断言 | `weeks/week02/issue-review.md` §十 早就登记了 16 条 → 改写为「已决修正未被反向同步」 |
| **3-3** | 用「14 BCNF + 3 反规范化」写 v1.0 文档 | 与 18 表新口径核对 | 现行口径是 **15 纯净 BCNF + 3 受控冗余**（14+3 是 17 表时代的） |
| **3-4** | `stocker.html` 用 `a[12]` 取 `alert_level` | 截图发现整列空白 | 视图 14 列，`alert_level` 是第 13 列 → **`a[9]`**；同时补 `WHERE alert_priority < 5` |
| **3-5** | 以为 `.cart-sheet` 能改 `.offcanvas.offcanvas-bottom` 的高度 | 面板只露 2 行，实测 `height=242px` | 优先级 0,1,0 压不住 0,2,0 → 选择器改 **`.offcanvas.cart-sheet`** |
| **3-6** | 用脚本替换模板时把 `{% endblock %}` 换成了 `{% block scripts %}` | `/manager` 直接 500 | Jinja 报 `Unexpected end of template` → 补回 `{% endblock %}` |
| **3-7** | 校验基线时给 `sqlcmd` 加了 `-h -1`、漏了 `-s '\|'` | 行数 72 vs 80、每行都不同 | **验证器本身也要被验证**：去掉 `-h -1`、补 `-s '\|'` → 293/293 差异 0 |
| **3-8** | 三次"编码"事故 | BOM/CRLF 检查、`git diff --stat` 整文件重写 | ① `Set-Content -Encoding utf8` 给**提交信息**加了 BOM（首字符变 `\ufeff`）② `edit` 工具会**剥掉 `.sql` 的 BOM** ③ `write_text(newline="")` 把 **CRLF 抹成 LF** |
| **3-9** | 无头 Edge 截图里柱子只有一半高 | 数据明显不对 | 截图发生在 **Chart.js 动画中途** → 加 `--virtual-time-budget=5000` |
| **3-10** | 「业务索引 204 个」 | 与重建汇总的 22 对不上 | `sys.indexes` 含 **105 个 `sys` 架构系统对象** → 必须 `JOIN sys.tables` |
| **3-11** | 「自定义角色 5 个」 | 库里只有 4 个 | **`public` 的 `is_fixed_role` 是 0** → 统计须加 `name <> 'public'` |
| **3-12** | 用「商品 × 杯型 × 糖度」判配方覆盖率，得到几十个"缺失" | 与文档「58 组合只 55 有」矛盾 | 糖度不是覆盖维度（无糖本就不耗糖类原料）→ **该图判定为语义不可靠、不发布**，改用销量榜 |
| **3-13** | 在单引号 here-string 里把 SQL 的 `'` 写成 `''` | SQL Server 报「`PK` 附近有语法错误」 | `@' … '@` 内引号**不需**双写（双写只适用于普通单引号字符串） |
| **3-14** | 写含中文的 `.ps1` 却存成无 BOM 的 UTF-8 | `powershell` 5.1 报一堆 `Unexpected token`、中文变 `AS 鍊?FROM` | PS 5.1 按 ANSI 读无 BOM 的 UTF-8 → **`.ps1` 含中文必须带 BOM** |

> **纪律**：AI 的产出只有两种状态 —— **能被命令复算的，和不算证据的**。

## 5. 提示词是怎么记录的

本阶段同样采用**长 Agent 会话 + 结构化提炼**，而不是逐条粘贴对话：

| 环节 | 做法 |
|---|---|
| 固定开场 | `harness/prompts/agent-session-start.md`（开工对齐 SOP） |
| 需求来源 | 用户直接发指令；每次由 AI 先给**方案选项 + 代价**，用户拍板 |
| 记录落点 | 周报（`weeks/week05`—`week07`）+ Issue 文档（`harness/issues/011`—`015`）+ 本文档 |
| 验证证据 | `project/tests/`（14 项回归 + 38 条应用测试 + 三份基线）、`weeks/submissions/v1.0/result/`（30 组截图） |

> **提示词不可追溯的部分如实说明**：本阶段的对话是连续长会话，
> 本文档记录的是**每次任务的目标、AI 给的关键输出、以及人工改了什么**，
> 而不是逐字复刻的 prompt。判断依据是最终产物能否被命令复算（见 §3 末的纪律）。
