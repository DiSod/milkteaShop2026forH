### 3.3 第 3 页（0:40—1:08）· ER 模型

> 这是最终 ER 图，**18 个实体、31 条联系**，每条联系都落成了外键，图上的 R01 到 R31 就是编号——**图上没有一个编号是装饰**。

### 3.7 第 7 页（2:16—3:01）· 一次点击，穿过六层 ★

**手指从第 1 格开始，一格一句，匀速向右。**

> （1）页面上只有一个表单：**数量、原因**，没有别的逻辑。
> （2）**路由**只做一件事——把这两个值取出来；21 条路由都是这个角色。
> （3）到 **service**：数量是不是正数、会不会把结存减成负数、原因填了没有——**八类业务错误都在这一层抛**。
> （4）进 **dao**：SQL 里只有问号占位符，参数是单独交给驱动的；**全项目没有一处字符串拼接**。
> （5）到 **SQL Server**：CHECK、外键、权限，**真正拦住脏数据的是库，不是代码**。
> （6）结果回填：一句 flash、一个新数字。

> 所以同一次报损，留下三样东西：页面上那句"已登记报损"，控制台的一行日志，还有流水表的一行。

## 5. 可能被问到的问题（每条 30 秒内答完）

| 问题 | 答法 |
|---|---|
| 为什么不用 ORM？ | 课程要看 SQL 能力，也要参数化查询。三层里只有 dao 写 SQL，参数化集中在一处，拼接 SQL 一处都没有。 |
| **怎么证明是参数化，不是拼接？** | 现场做：登录框输入 `' OR 1=1 --`，页面回「手机号或密码不正确」，**不报 SQL 错误、也不会登进去**。里面是 `?` 占位符，值是单独交驱动的。 |
| 18 张表还能再拆吗？ | 15 张已经是纯净 BCNF，剩下 3 张是刻意的冗余列，拆了要多一次聚合；它们都有唯一写入口保证一致。 |
| 券为什么要拆两级？ | 面额、门槛是"这类券"的属性，跟具体券号无关；不拆就要在 12 张券上重复存同样的面额，改一次要改 12 行。 |
| 会员为什么看不到积分流水？ | 数据库角色没有那张表的读权限；放开就等于让收银员能读全部会员的流水。界面给了提示，没有假装有数据。 |
| 两个人同时下单会超卖吗？ | 会——查库存和扣库存之间有窗口。v2.0 按原料 ID 排序加锁，并写并发脚本先复现再证明解决。 |
| 迁移脚本能重复跑吗？ | 不保证，课程也不要求；README 写了运行前提和失败恢复（从 00 重跑）。 |
| 数据是真的吗？ | 种子生成器按业务规则造了 1,963 单、2,629 条明细，约束全部通过；每张证据图都有可重跑的命令。 |
| 界面为什么是 Material Design？ | 只换皮肤不换框架：一个 css 加 14 个模板，全部离线内置，没有构建步骤，46 条测试零影响。 |
