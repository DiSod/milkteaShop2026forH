# submissions · 阶段提交归档

四次阶段作业的**提交快照**。每个版本目录在提交截止时冻结一份，之后不回改。

> 归档的意义：课程要求"每个阶段结束后提交一个能够运行和复现的项目版本"。快照让"当时提交了什么"可追溯——这在后续答辩与组内复盘时是关键证据。

## 归档内容（每次提交）

依据 **`course/lecture-week04.md`** 的「阶段作业：可运行的数据库原型（v0.1）」一节
（该节是提交物清单的**权威依据**；`lecture-week01.md` 的《提交作业要求》只有 5 项粗颗粒，**没有 `result/` 与 `ai_log`**）。

| # | 提交物 | 课程要求 | 我们的落点 |

### 阶段报告的重点（课程原文，第 27—30 行）

> 重点应该说明：
> - 经营场景与业务流程，**哪些信息进入数据库、哪些暂不进入，为什么**

> - **完整性约束：角色与权限如何划分，给出正反例**

## 归档规则

1. 提交截止**前**从 `project/` 与 `weeks/` 复制快照，**不要**在 `submissions/` 里直接开发
2. 归档后该目录**不再修改**
3. `ai-log.md` 与 `contributions.md` 汇总该阶段全部周度的记录
4. ⚠️ **例外：`result/` 属提交物本体** —— 截图与运行记录无法"从别处复制"，**直接在其中生成**
5. ⚠️ **截图只是证据**（课程第 63 行）—— `code/` 与 `result/` **两者都要有**，缺 SQL 脚本的截图不算数
6. 文件名遵守 [`01-layout-and-naming.md`](../../harness/conventions/01-layout-and-naming.md) §1：**全英文、全小写、`-` 连接**
