## 〇、来源声明与填写说明

### ⚠️ 模拟数据声明（必读）

> 本表以 **蜜雪冰城的产品结构与价格带**为参考 —— 低价带（**2—12 元**）、以**柠檬水 / 果茶 / 珍珠奶茶 / 冰淇淋**为主力品类。
>
> **但配方用量不是任何品牌的真实配方** —— 蜜雪的配方并未公开。用量参照**行业常见区间**取值，**属模拟数据**。
>
> 这一点已在 week1 §5.3「前置风险」第 1 条预留说明："配方数据全为自建，合理性需说明；用量参照行业公开配方区间，并在报告中标注为'模拟数据'"。

### 与 week1 的一处偏差（需小组确认）

week1 §1.1 列的品类是 **4 类**（经典奶茶 / 水果茶 / 纯茶 / 季节限定）。
本草案**增加第 5 类「冰淇淋与奶昔」** —— 理由是低价带奶茶店的冰淇淋是主力产品线之一，且它是**唯一不经过茶底/奶基底**的成品结构，对配方表是一个有价值的对照样本。

### 填写要求

| 项 | 要求 |
|---|---|
| **编号** | 成品 `P0xx`、原料 `I0xx`，**连续不跳号** |
| **单位** | 原料基本单位统一为 `g` / `ml` / `个` / `根` / `张` —— **不做单位换算**（采购也按基本单位记）<br>**散装物料（茶叶、鲜果、糖浆）一律按 `g` / `ml`；只有计件包材用 `个` / `根` / `张`** |
| **用量口径** | 见下文「干重当量」约定 |
| **补货点 / 目标水位** | 当前值为**估计值**，待造数阶段按实际销量校准 |

### 记账口径约定（与 D2 配套）

> **煮制 / 泡制不产生库存流水。**
> 例：干珍珠 100g 煮成熟珍珠 200g —— **不入账**（物料还在店里，只是形态变了）。台账上的"珍珠"数量始终是**干重当量**。
> 因此配方里"珍珠"的用量是**干重**，报损称重后也须**折算回干重**登记。

| 项 | 约定 |
|---|---|
| **杯型** | `M`（中杯）/ `L`（大杯） |
| **糖度** | `ANY`（用量与糖度无关）/ `S30` / `S50` / `S70` / `FULL` |
| **`ANY` 的含义** | 该原料用量**不随糖度变化** —— 用哨兵值而非展开 5 档，避免更新异常 |

### 📌 配方补充说明：为什么补的是这 4 款

原本考虑补「布丁奶茶」「芋圆奶茶」，**最终没有补** —— 理由是：

> **布丁奶茶 / 芋圆奶茶 与 珍珠奶茶 的固定配方完全相同，差别只在"加什么小料"。**
> **而小料不属于固定配方** —— 它是订单级的**可选增量**，落在 `tbl_topping`（见 D-06），
> 通过 `qty_per_serving` 参与扣料，**不写进 `tbl_recipe`**。

如果把它们也写进配方表，会出现**三款成品的配方行完全相同**的情况 —— 那看起来像数据重复，实际也确实是重复。

**正确做法是把这件事"说明白"，而不是"用数据重复表达"**：

| 成品 | 固定配方（`tbl_recipe`） | 可选加料（`tbl_topping`） |
|---|---|---|
| 珍珠奶茶 P004 | 红茶 + 植脂末 + 果糖 + 中杯 + 吸管 | 珍珠 |
| 布丁奶茶 P007 | **同上，一字不差** | 布丁 |
| 芋圆奶茶 P006 | **同上，一字不差** | 芋圆 |

> 这恰好是**选奶茶店的那个理由的实证**：**固定配方与小料是两层结构，不能混在一张表里。**
> 本条也应当在答辩时讲出来 —— 它解释了"加了小料的订单，扣料为什么是两路"（见 D-06 的「配方展开是两路」）。

**所以补充的 4 款，是按「结构差异」选的，不是按「口味」选的**：

| 补入 | 它补的是哪一种结构 |
|---|---|
| P012 四季春茶 | **纯茶** —— 原料数接近下限 |
| P016 原味奶昔 | **冰淇淋 + 液态**，且**带糖度** |
| P022 杨枝甘露 | **原料数上限**（6 味原料 + 2 项包材） |
| P021 脆皮甜筒 | **异形包材** —— 没有杯 / 盖 / 吸管 |
