## 核心设计与技术亮点

### 1. 招牌视图：理论可做杯数推导（`vw_product_stock_availability`）
- **痛点与争议**：“既然已经用了单库反冲倒扣，还需要算‘还能做几杯’吗？”
- **辩证闭环**：两者是**事前决策**与**事后记账**的正交互补。
  - “反冲倒扣”保证了总库 `qty_on_hand` 在交易后的绝对真实性；
  - “还能做几杯”在交易发生前，运用“木桶短板理论”：
    $$\text{可用杯数} = \min_{\text{配方物料}} \left( \left\lfloor \frac{\text{物料实存}}{\text{配方用量}} \right\rfloor \right)$$
    并取全糖 worst-case 与 `is_sold_out` 人工沽清状态机融合，为店长备料巡检和前台点单提供理论上限。

### 2. 账实守恒审计：进销存台账自洽平衡（`query.sql` Q4）
- 对全库 60 种原料、13,851 条流水进行条件聚合对账：
  $$\text{流水理论结存} = \text{期初库存} + \sum(\text{采购入库}) - \sum(\text{销售耗用}) - \sum(\text{打烊报损})$$
- 经与物理在手实存 `qty_on_hand` 逐物料比对，**全库 60 种原料 100% 达成 `variance = 0.000`**，数学证明系统满足物质守恒。

### 3. 安全隔离：RBAC 4 岗位授权与负例防御（`08-security/role.sql`）
- 使用 SQL Server 原生无登录安全主体（`WITHOUT LOGIN`），杜绝环境污染；
- 3 组越权负例拦截均由 SQL Server 引擎底层抛出 `Error 229`，并通过 `TRY...CATCH` 完美断言：
  1. 收银员篡改配方表 `tbl_recipe` -> **拦截成功**（防偷工减料）；
  2. 制作员窥探会员手机号与档案 `tbl_member` -> **拦截成功**（防客户隐私泄露）；
  3. 库管员删除前台交易订单 `tbl_order_header` -> **拦截成功**（防单据伪造与销赃）。

## 权限设计的取舍与已知边界（摘要）

> **完整说明见** [`project/docs/design-notes.md`](../../project/docs/design-notes.md) 第一节。
> 按 `01-layout-and-naming.md` §5「禁止同一份内容在两个地方各自演化」，此处只留摘要。

### ① `role_maker` 用**视图**读库存，而不是直接读表 ✅ 有意的收紧

| | |
|---|---|
| week1 §2.2 原文 | 制作员**只读**库存、库管员**可写** |
| 实际实现 | `role_maker` 对 `tbl_ingredient` **零直接权限**，只能经 `vw_product_stock_availability` 读"还能做几杯" |
| 为什么更好 | 视图**不暴露** `moving_avg_cost`（成本）、`reorder_point`（补货点）等敏感列 —— **更细粒度的授权** |

```
实测：直接读 tbl_ingredient          → ❌ 拒绝 SELECT
      经 vw_product_stock_availability → ✅ 57 行
```

### ② ⭐ 已知边界：跨岗位的业务动作，**纯 RBAC 无解**

**实测现象**：收银员能开单，但**反冲扣料被拒**。

| 角色 | 能下单 | 能写库存流水 | 能扣库存 |
|---|---|---|---|
| `role_cashier` | ✅ | ❌ | ❌ |
| `role_stocker` | ❌ | ✅ | ✅ |

**根因**：SQL Server 权限**按对象判定**，而「下单一笔」跨越了**被第三组分离刻意分开的两个域**。

| 目标 | 要求 |
|---|---|
| week1 §2.2 第三组：岗位制衡 | 任何人**不能同时握有**订单域和库存域 |
| 裁决 D1：反冲倒扣 | 下单**必须同时**扣库存 |

**两个目标打架** —— 分离做到了极致，恰恰让反冲无法执行。

**正解**：把"开单 + 扣料"封成**存储过程 + `EXECUTE AS OWNER`**，
只给收银员 `EXECUTE` —— **权限边界保留，业务动作能完成**。

> 🎯 **第 11—12 周「存储过程」的天然素材**。
> **v0.1 不修** —— 现在改会破坏第 4 周"越权失败"演示的完整性；
> 而且 `CREATE PROCEDURE` / `EXECUTE AS` / 所有权链**本来就还没学到**。

> 💡 **这个"做不到"其实是好消息**：它证明第三组分离**真的生效了**，不是纸面文章。
> 答辩话术见 design-notes。
